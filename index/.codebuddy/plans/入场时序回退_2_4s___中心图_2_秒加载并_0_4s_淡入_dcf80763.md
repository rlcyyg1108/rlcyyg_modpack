## 需求概述

对个人主页的入场体验做一次「回退 + 微调」，不改动任何信息结构、排版与交互方式。

## 核心功能

- **入场总时长回退为 2.4 秒**：圆盘放大淡入、刻度环浮现、板块文字浮现、左右信息栏与四角面板上浮、装饰延伸线与弧线生长、角落版权署名出现，各段的延迟与时长全部恢复到放大前的原始值，先后顺序与缓动曲线不变。
- **中心图片第 2 秒开始加载**：进入页面后前 2 秒圆盘中心保持空白（无发光边框、无裂图），第 2 秒起才请求头像。
- **中心图片 0.4 秒渐进显现**：图片就绪后不再是瞬时出现，而是在 0.4 秒内透明度由 0 平滑过渡到 1，正好接上入场收尾，观感是「头像从环心里浮出来」。
- **其余行为不变**：静置无波纹、四个板块切换、圆盘拖拽、链接卡片轮盘、移动端重排、交互提前打断入场等均保持现状；打断时中心图仍在第 2 秒开始加载。

## 视觉结果

打开页面后按原节奏约 2.4 秒走完入场；中心头像在约第 2 秒开始请求，并在 0.4 秒内柔和浮现，与版权署名收尾基本同步，不再出现「啪」地弹出来。

## 技术栈

纯静态站点，沿用现有 HTML + CSS + 原生 JS（ES6）写法，无框架、无构建。复用既有机制：`body.boot` / `body.anim-in` 驱动入场、`bootTimers` 统一管理入场计时器、`#hubImg.pending` + `data-src` 承载延迟加载。

## 现状核实（已读取确认）

- `index/style.css` 第 1308/1313/1325/1329 行等仍为上一轮 ×1.5 后的值（1.5s、1.35s、1.2s…），第 1302 行注释写着「1875 / 3600 / endBoot 里的 2550」。
- `index/style.css` 第 127 行 `#hubImg` 过渡仍为 `opacity .25s ease`。
- `index/script.js` 第 1495 行 `2550`、第 1539 行 `1875`、第 1547 行 `3600`、第 1550 行 `setTimeout(loadHubImg, 3000)`。
- `index.html` / `index/test.html` 的中心图已是 `class="pending" data-src="…"`，本次不需要改动。

## 实现方案

### 1. 入场序列恢复原始时长（style.css）

| 选择器 | 当前 | 恢复为 |
| --- | --- | --- |
| `body.boot/#anim-in #ringWrap` | bootRing 1.5s / .075s | bootRing 1s / .05s |
| `body.boot/#anim-in #decor` | 1.35s / .675s | .9s / .45s |
| `body.boot/#anim-in #labels` | 1.05s / 1.275s | .7s / .85s |
| `.panel-left` / `.panel-right` | 1.2s / 1.5s | .8s / 1s |
| `.corner-deco` | 1.2s / 2.1s | .8s / 1.4s |
| `.corner-panel.visible` | delay 1.5s / dur 1.2s | 1s / .8s |
| `body.boot #deck/#linkPanel/#linkHead/#linkBadges` | delay 1.5s / dur 1.2s | 1s / .8s |


`#decoLines` 四组过渡成对恢复：`.dline` 隐藏态 `.75s/.75s → .5s/.5s`；`.show-* .dline` `.75s/0s → .5s/0s`；`.arc` 隐藏态 `.825s → .55s`；`.show-* .arc` `.825s/.675s → .55s/.45s`。

同步修改注释：段首「×1.5（总入场 2.4s → 3.6s）」改回总 2.4s；「统一到 1.5s」→「统一到 1s」；「3.6s 摘掉 boot」→「2.4s」；`#decoLines` 段首「生长（共 1.5s）…」改回「共 1s」并删掉 ×1.5 说明。

### 2. JS 计时器恢复（script.js）

`1875 → 1250`、`3600 → 2400`（注释改为「2400 = CSS 入场总时长」）、`endBoot()` 内 `2550 → 1700`（注释「最长 ~2.4s」→「~1.6s」），并把 `endBoot()` 注释里的「1.5s 延迟」「一秒半多」改回「1s」「一秒多」。第 1302 行的三个数值说明同步更新。

### 3. 中心图 2 秒加载、0.4 秒淡入

- `script.js` 第 1550 行 `setTimeout(loadHubImg, 3000)` → `2000`，配套注释改为第 2 秒（仍保留「不进 bootTimers，交互打断不取消」的说明）。
- `script.js` 中 `loadHubImg` 上方注释「第 3 秒」→「第 2 秒」。
- `style.css` 第 127 行 `#hubImg` 过渡：`opacity .25s ease` → `opacity .4s ease`（摘 `.pending` 后即走这条过渡）。
- `style.css` 中 `#hubImg.pending` 注释「第 3 秒才注入 src」→ 第 2 秒，并说明摘类时走 `opacity .4s`，所以是浮现而非闪现。

### 4. 时序校验

入场最后到位的是 `.corner-deco`：1.4s + 0.8s = 2.2s < 2.4s，摘 `boot` 时不会截断动画。中心图 2.0s 注入 src（本地文件基本瞬时完成）→ 摘 `.pending` → 0.4s 后约 2.4s 完全显现，与入场收尾对齐。`prefers-reduced-motion` 下过渡被全局关闭，表现为直接显示，属既有行为。

## 风险与边界

- 仅改 `index/style.css`、`index/script.js` 两个文件，两份 HTML 结构不动；不触碰轮盘几何、卡片轮盘、莫比乌斯带、移动端重排与已删除的波纹代码。
- 局部替换、不重写整文件；改数值必须同步改注释，避免注释与代码不一致。
- 图片加载耗时超过 0.4s 时，淡入从加载完成那一刻起算，仍然平滑，不会回退成闪现。
