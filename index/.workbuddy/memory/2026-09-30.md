## 几何（关键，踩过的坑）
- 竖椭圆：`x = cx − rx·cos φ`，`y = cy + ry·sin φ`，`φ = 2π·(k−pos)/N`。**φ=0 → 最左 = 最近 = 最大**。
- 深度 `depth = (1+cos φ)/2`，缩放 `s = 0.42 + 0.58·depth`。**角度均分**是「2 张到 120 张都自适配」的全部秘密，间距自然可以为负（重叠）→ 靠 `z-index = 100 + depth*300` 解决（越大越靠上）。
- 未选中卡**尺寸恒为 150×58**（不随条目数变），只有当前卡按档位放大：`S≤6→250 / M 7–12→292 / L 13–16→336`；`>16` 不展开、走长条。
- 卡片宽度上限是**整条带宽** `limR − limL − 10`，不是「以最近点为中心的两倍」——放不下时由 x 的钳位整体右推，否则 1024 宽屏上 M 档会被压到 180。
- `transform = translate3d(x,y,0) translate(-50%,-50%) scale(s)`：右边两个 translate 顺序反了就不会居中；`width/height` 只写、不进 transform，所以 CSS 里**不能有 transform 过渡**（会拖尾），只过渡 width/height/描边。
- `.dcard` 是 `display:flex; flex-direction:column`，`.dc-list{flex:1;min-height:0;overflow:auto}` → 卡片高度被 JS 钳住时列表自己滚，不会撑破卡片。
- `ROW_H=38 / HEAD_H=48 / LIST_PAD=22` 是量出来的（14px/1.3 + 12px/1.3 + padding），改 CSS 字号必须同步改常量。

# 改动 11：轮盘彻底重做 → 卡片环 + 中心展示区（已落地）

## 用户否掉「选中卡放大」的原因（别再走回头路）
1. 尺寸随位置变，但 CSS 有 `width/height .38s` 过渡 → **位置每帧即时、尺寸慢半拍**，转起来大小与位置对不上。
2. 当前卡 250×222、邻居 147×57，中心只差 ~110px → **必然压住上下两家**（选到 13 条的卡会一次吞掉 6 张）。
3. 远端 `S_MIN=0.42` → 卡片 63×24、字 8px，变成"一团雾"。
4. 椭圆 rx≈150 / ry≈330 → 读起来是竖梯子不是椭圆；**等角度均分在大离心率椭圆上间距不均**（远端挤一堆、近端空一块）。

## 新方案（用户拍板）
- 卡片**恒定 120×58**、不缩放、不随条目数变；**放弃远端缩放**。
- 椭圆**拉宽**，中间空出的方块 = `#linkPanel` 展示当前选中卡的网站（一列一条）。
- 仍以**最左端 = 最近点 = 选中项**。
- 窄屏（<1500 或带宽不够）→ **方案 C**：退化成「左侧一列卡片 + 右侧展示区」，不要椭圆。
- 卡片宽 120 / 高 58；个人链接改回**竖排一列**。
- **重叠必须单向链式**：A 压 B、B 压 C…… 不是「我叠他、你叠他」。

## 实现要点
- **等弧长均分**（不是等角度）：`buildArc()` 采样 512 点累弧长 → `arcAt(s)` 二分查表插值。这是修掉"东一块西一块"的关键。
- **链式叠压**：`z = 2000 − round(|f|·20) + (f>0 ? 1 : 0)`（f 是环上的最短带符号偏移）。|f| 越大 z 越低 ⇒ 单向链；环闭合做不到严格循环，**断口落在最远端那张**（最不显眼）；|f| 相同用符号定序防抖动。
- **不透明**：底色 `rgb(26~56, …, +3)` 由 JS 按纵深 d 每帧写；纵深只调**亮度**，不调 opacity（透明会让后面的字透上来）。选中卡 = `rgb(62,62,68)` + `.dcard.cur::before` 左侧 3px 白条。
- **展示区尺寸是算出来的**：卡片中心在椭圆上、半宽 60/半高 29 ⇒ 纵向落在面板高度内的那几张，横向最多退到 `rx·sqrt(1−k²)`（k=(h/2+29)/ry），再减 60 才是面板半宽。扫一遍高度取面积最大的一组 → 1920 上得 ~230×536。**别手写死尺寸，会撞卡。**
- **列模式不能环形归一化**：`f = k − pos` 不做取模，否则滚到末尾时第一张会"接"到最后一张下面。只有椭圆模式才 wrap。
- `#deck` 加 `overflow:hidden`（列模式有卡片排在窗口外，会被裁掉，也不会撑出滚动条）。
- **上浮动画挂在容器**（`#deck / #linkPanel / #linkHead / #linkBadges` 用 `fadeIn .35s`），**不能挂 `.dcard`**——卡片的 transform 每帧由 JS 写，关键帧会盖掉它。`body.boot` 里补 `animation-delay:1s` 与其它面板对齐。换卡时 `.pn-list` 重播 `panelSwap .26s`（`animation:none → 重排 → 还原`）。

## 修掉的 bug
- **链接点不开**：`setPointerCapture` 把 pointerup 重定向到卡片 ⇒ click 目标变成卡片而不是 `<a>`。**已删除捕获**，move/up 改挂 window。
- **简介行塌陷**：`it.d || ' '` 里的普通空格是可折叠空白 ⇒ 行高从 38 掉到 22。改用 `'\u00a0'` + `.pn-inote{min-height:1.3em}`。
- **滚轮抢走列表滚动**：`window wheel` 只放过 `#linkStrip`；现在放过 `#linkPanel`。

## 删除的东西
`#linkStrip` / `.st-head` / `.st-list` / `renderStrip()` / `STRIP_OVER` / `TIERS` / `tierW()` / `S_MIN` / `HEAD_H` / `LIST_PAD` / 卡片内嵌的 `.dc-list`；类名改 `dc-item/iname/inote` → `pn-*`。

# 改动 12：修展示区跑板块 / 黑块 / 叠压方向；卡片环改「顶点独占」（已落地）

## 头号 bug（一个 CSS 疏漏同时造成 4 个症状）
`#linkPanel` 的基础规则里写了 `display:flex`，它在**同优先级、更靠后**的位置，
把上面的 `#linkPanel{display:none}` 反压了回去 ⇒
① 刚进站左上角一个黑块（面板在静态位置、还没被 measure 定位）；
② 展示区在**所有**板块都显示；
③ **进了链接板块反而滚不动**——`body.deck-on #linkPanel{display:block}` 优先级更高，
   父级变回 block ⇒ `.pn-list` 的 `flex:1 + min-height:0` 失效、高度撑到内容高，
   父级 `overflow:hidden` 直接裁掉（所以在别的板块反而能看到滚动条，倒反天罡）。
**教训：显形规则必须把 display 值写全（deck-on 下 #linkPanel/#linkBadges 写 flex、#deck/#linkHead 写 block），
基础规则里绝不写 display。**

## 卡片环：四个顶点各由一张卡独占（替换等弧长均分）
纯等弧长均分**做不到**「上下两端各只有一张卡」：顶点要正好落卡要求 N 是 4 的倍数
（N % 4 ≠ 0 时必定有两张卡骑在顶点两侧叠在一起，N=18 时就是这个症状）。
`buildRing(N,P)`：左/下/右/上四个顶点各占一张，余下 N−4 张在四段弧里均分
（`ex = r===0?[0,0,0,0] : r===1?[1,0,0,0] : r===2?[1,0,0,1] : [1,1,0,1]`，Q1/Q4 互为上下镜像以保对称）。
`slotAt(u)` 在相邻卡位间线性插值 ⇒ 拖动仍连续（实测最大位移 1.25× 名义步距）。
N<4 退回等弧长均分。

## 叠压方向修正
旧式 `z = 2000 − |f|·20 + (f>0?1:0)` 是**两侧各排各的**，等效于在上下顶点各断一次，
顶点那两张 z 只差 1、还随小数位置翻转 → "方向不准"。
改为 `ord = (f + N/2) mod N`，`z = isCur ? 3000 : 2000 − round(ord/N·1200)`：
沿环**一个方向**严格单调递减（我叠你、你叠他），唯一断口落在最右顶点那张，
且断口后的第一张（= 最右顶点卡）z 高于两侧邻居。

## 其余
- `CARD_W 120 → 100`（连带 `.dcard` padding 11→9 / gap 6→4、`.dc-name` 16→15px、`.dc-count` 10→9px）。
- `#linkPanel` 背景 `rgba(14,14,16,.84) → rgba(18,18,22,.58)` + `backdrop-filter:blur(5px)`。
- `.pn-iname/.pn-inote` 去掉 `nowrap+ellipsis`，改 `overflow-wrap:anywhere` 允许换行（长站名不再被砍）。

- `ROW_H` 已删（换行后行高不固定，展示区靠滚动）。

# 改动 14：等间隙环 + 当前卡放大（已落地）

用户反馈：「轮转的间距还是不均匀，左边明显比右边多俩」+「让被选中的卡片稍微变大一点」。

## ① 卡位解算重写：从「四顶点钉卡 + 四段等弧长」→「处处等【方框间隙】」
- 根因 1：弧长相等 ≠ 视觉间隙相等。椭圆靠近上下顶点时弧近乎水平，卡片 100px 的**宽度**会把间隙吃掉，
  所以旧版实测两端间隙 0、16，两侧却 73。
- 根因 2（「左边多俩」）：旧版四个顶点各钉一张、剩余 N−4 张在四段弧里均分。N=18 时 inner=14、q=3 r=2，
  多出来的两张分给 Q1/Q4（都在左半）⇒ 左 10 右 8。
- 新 `buildRing(arc, N)`：从左顶点出发一步步「走」，每步的弧长增量 d 由
  `boxGap(arcAt(s), arcAt(s+d)) === c` 解出（牛顿步，间隙对 d 单调、斜率≈1，几轮收敛）；
  常数 c 由「走满 N 步正好回到 P」**二分**确定（44 次）。N<6 仍走等弧长。
  代价：N 为 4k+2 时上下顶点各有一对卡**对称地骑在顶点两侧**（但它们之间是干净的正间隙，不是叠一起）。
- 实测（1920 宽、N=18）：18 对间隙全部 49.5~49.6，左/右 = 9/9，每格弧长步距 108→160（1.48×）。

## ② 拖动插值：不能用弧长线性插值，改 PCHIP
线性插值的速度是**台阶式**的（每格步距本就不等），实测相邻小步位移差到 1.4× ⇒ 拖起来一跳一跳。
先试过「把步距当速度序列做周期 Catmull-Rom 再积分」，**错了**：Hermite 单格积分
= (a+b)/2+(m0−m1)/12 ≠ 该格步距 ⇒ 整数节点处不闭合（实测速度起伏飙到 124×）。
正确做法：对**累积位置**做单调三次插值（PCHIP / Fritsch–Carlson），单位间距下切线
`m_k = 2·step[k−1]·step[k] / (step[k−1]+step[k])`（调和平均，必落在两格步距之间 ⇒ 严格单调）。
节点精确命中 `ring[k]`、跨节点一阶连续、闭合仍是 P。新增 `buildStep(ring)` → `G.step`。
实测：相邻小步突变 1.04~1.11×（原 1.41），整圈速度起伏 1.5~2.2×（等间隙的固有代价，平滑不跳）。
`slotIdx()` 已删（被 slotAt 吸收）。

## ③ 当前卡放大
- `CUR_W=118, CUR_H=68`（×1.18），`layoutDeck()` 里只改 width/height、中心不变；
  `.dcard` 加 `transition: width/height .22s`（**transform 绝不能加过渡**，否则拖尾）。
  字号跟着提：`.dcard.cur .dc-name 16px`、`.dc-count 10px`。
- `measure()` 联动：椭圆两端按 `CUR_W/2` 留边（`nearX/farX`）；面板孔径额外受
  `apexHw = rx − CUR_W/2` 约束；`maxPH` 用 `CUR_H`；列模式 `colX = limL + CUR_W/2`、
  `pitch = CUR_H + CARD_GAP = 74`。

## ④ 移动端顺手修的穿帮
一列模式列表比可视区长，两端卡片会排到带外（上压标题、下压徽章）。`measure()` 里按**视口坐标**
给 `#deck` 挂一条上下渐隐 mask（`linear-gradient`，fade = CUR_H×0.7），越界卡片化在边缘；
椭圆模式清空 mask（卡片本就全在带内）。

## 测试（p1~p4 全绿）
- p1 改断言为：非当前卡 100×58 / 当前 118×68、间隙 `(max−min)/mean < 1%`、左右卡片数相等、
  顶点处 1~2 张对称卡、当前卡在最左顶点且不越界。65 项全绿。
- p2 断言改：gapEven（容差 `max(0.5,|mean|·0.02)`，N<6 跳过）、noOverlap（仅 mean≥0 时）、
  lrBalance（|L−R| ≤ N%2）、curBig、ringPin、zChain。14 组全绿。
- **p3 的基准要换**：等间隙后「每步名义位移 = (P/N)/8」已经不成立（步距本就不等），
  改成测「相邻小步位移之比」（连续性，阈值 1.2）+「整圈最快/最慢之比」（起伏，阈值 2.4）。
- p4 改：卡片尺寸分当前/非当前；带内至少 4 张完整卡 + 容器挂了含 topLim/botLim 的渐隐 mask。
- 新增 `ringT.mjs`：打印真实页面的环状态，并验 `slotAt` 严格单调（2000 点采样 0 回退）与闭合 = P。
- 旧的 `d1/d2/d3/n1/n2` 是重写前的脚本（120×58、老 z 链定义），**已作废**，以 p1~p4 为准。

# 改动 16：当前卡改钉【上顶点】+ 去纵深压暗 + 描边动画换 transform & 减速 10 倍

用户诉求四条：① 去掉轮转右侧的阴暗效果；② 上下各只留一张卡、左右数量相等；
③ 选中的卡改到最上方；④ 卡片描边动画整体速度 /10，且「不连续、不流畅」要修。
另外重申：**不要再跑测试，直到他下令恢复**（本轮只做了 3 次针对新代码的定点核对）。

## ① 卡位解算重写：只解左半圈 + 镜像到右半
- `buildRing(arc, N)`：`A = 3P/4` 是上顶点的弧长（椭圆四象限弧长严格相等 ⇒ 上顶点正好在 3P/4）。
  slot 0 钉在 A（= 当前卡）。
  - 偶数张：左半圈走 `m = N/2` 步正好落在 `P/2`（下顶点）；
  - 奇数张：走 `m = (N-1)/2` 步后，从最后一张跨过下顶点到它的镜像也要**正好算一格**，
    二分条件变成 `stepAt(A+d[m]) > P - 2·d[m]`。
  - 右半圈 = 左半圈的**镜像**（反射 x→2cx−x 在弧长上就是偏移翻号）：`pos[m+j] = A − d[idx] + P`。
    左右张数/间隙因此必然相等，不再是「凑」出来的。
  - 第一格用 `(CUR_W+CARD_W)/2`、`(CUR_H+CARD_H)/2` 当有效尺寸（放大的当前卡在上顶点，
    邻居是横向贴过来的），所以选中卡两侧的间隙和其他地方一样。
- 实测（1920 宽、N=18）：上 1 张（当前卡）、下 1 张、左 8 右 8、轴上 2 张、**18 对间隙全是 45.7**。
  N=2/4/6/20/40 同样「上1 下1 左右相等」；N 奇数（5/9/19）下顶点必然是**一对对称卡**，
  这是「上1+下1+左右相等」在奇数张下无解的必然取舍（左右的相等优先保证）。
- `if (N < 2)` 才退回均分，其余全走求解器。

## ② 展示区尺寸改用【真实卡位】试出来
- 顶点位置一换、当前卡一放大，原来的解析式（`rx·√(1−k²)` + `apexHw`）就全废了。
  现在把每张卡的矩形（含放大的当前卡，各边 +6px 余量）算进一个数组，`fits(w,h)` 逐张做矩形相交，
  扫高度 + 每个高度上二分最宽，取面积最大的一组。屏幕多大、卡位怎么变都自动收敛。
- 实测面板从 248×544 涨到 **278×640**（左右顶点不再有卡占位，洞变大了）。

## ③ 纵横两个方向留边的对调
- 水平：`nearX = limL + CARD_W/2`（左右顶点上是普通卡，不用再缩）；
  竖直：`ry = (bandH − CUR_H)/2 − 8`（上顶点是放大的当前卡，纵向最紧的是它）。

## ④ 去掉纵深压暗
- `layoutDeck` 里删掉 `d`（纵深亮度）与 `--ea/--eb`（描边亮度的纵深联动），
  非当前卡统一 `--fill: rgb(56,56,59)`、字色统一 `rgba(255,255,255,.92)`，当前卡 `rgb(66,66,72)`。
  远近关系只由 z 序表达。

## ⑤ 描边动画：改 transform 动，速度 /10
- 结构改为 `::before` = 渐变描边层（`z-index:-2`，左右各多出 120px）、`::after` = 底色层（`z-index:-1`）。
  原来 `.dcard.cur::before` 是左侧那道 3px 白条，**已撤**（八边形会把白条两端削成碎渣；
  选中现在由「放大 + 更亮底色 + 激进描边」三重表达）。
- 关键：动 `transform: translate3d(dx,0,0)` 而不是 `background-position`。
  ① transform 走合成层、位移是插值出来的，绝对连续（`background-position` 每帧重画渐变，
     就是他说的「不连续、不流畅」）；
  ② 45° 条纹水平位移 dx 的**轴向投影** = dx/√2，取 dx = 周期×√2 就正好走一个周期
     ⇒ 首尾图案完全重合、循环无缝。普通卡 60px → 84.853px；当前卡 56px → 79.196px。
- 速度：普通卡 1.5s → **15s**；当前卡 0.62s → **6.2s**（都是 /10）。
- 入场旋转：`spin` 下限从 1.5 格改成 0.6 格（N=2 时 0.28N=0.56 格被夹到 1.5 格 = 270°，太夸张）。
