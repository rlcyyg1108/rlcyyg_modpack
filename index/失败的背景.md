# 失败的背景尝试：双光带 X

> 一句话：把「一条会呼吸、会整体旋转的亮带」改成「两条反向旋转、交叉成 X 的光带」，
> 功能全部实现且可量化验证，但视觉上不成立 —— 已整体回退到改动前。

---

## 一、改动前的原始设计（当前已恢复到的状态）

- 单层 `#bgField`：150vmax 方块，`linear-gradient(0deg)` 对称渐变
  `#0d0d10 0% / #15151b 26% / #2c2c35 44% / #34343e 50% / …`，旋转由 JS 驱动。
- 亮度呼吸：`@keyframes bgBreath`（26s，opacity .86 ↔ 1）。**（回退之后又按要求单独删除，背景现为恒定亮度）**
- 运动：center 态 12°/s 被动自转；切板块 1s 内顺时针转到 0°（横）或 90°（竖）后停住。
- 角度表：`projects/links → 0°`、`interests/artists → 90°`。

---

## 二、尝试过的方案

### 结构

`#bgField` 拆成「容器 + 两条 `.bg-band` 子层」，每层各自 `rotate()`，用
`mix-blend-mode: lighten` 叠加（重叠处取较亮者，不叠色、交叉点不过曝）。

### 运动

| 场景 | 设计 |
| --- | --- |
| 中心态 | A（`\`）45° 起**逆时针**、B（`/`）135° 起**顺时针**，各 3°/s |
| 进板块 | 两条各走**最短路径**，1s 内剪刀式合拢成一条线；正好 90° 平局时 `\` 逆时针、`/` 顺时针 |
| 板块↔板块 | 同上，因方向互异，中途会张开成一个 X 再合拢 |
| 同轴切换 / 重复点击 | 1.4s「张开 45° 再合拢」（0.6s 开 + 0.8s 合） |
| 回中心 | 不主动张开，直接恢复反向自转，约 15s 自然掰成 X |

### 配色（两版）

- v1 冷灰：底色 `#0a0b10`，色标 `0/24/40/50/60/76/100`（`#0a0b10 / #14151d / #2b2c38 / #333440`），文字光晕冷白 `rgba(226,236,255,α)`。
- v2 纯黑白：底色 `#0d0d10`，色标 `0/38/45/55/62/100`（`#0d0d10 / #15151b / #2c2c35 / #34343e`）。

## 三、为什么失败

### 1. 亮度呼吸没删掉，换了个形式回来

两条带反向转 ⇒ 夹角在 90°↔0° 变化。**垂直时两条带覆盖面积最大、整屏最亮；收成一条时只剩一条带、明显变暗。**

实测全屏平均亮度：合并态 **31.0**，垂直态 **36.6**，差 **约 18%**，周期 15 秒。
而被删掉的原呼吸是 26s、幅度 14% —— 新方案更频繁、幅度更大。

### 2. 「X」根本不是稳定状态

夹角以 6°/s 变化，90° 只是**一瞬间**。绝大多数时间看到的是 30°–60° 的窄剪刀；15 秒后完全合成一条线。
首屏是 X，但从板块回到中心后**要等 15 秒**才重新成 X —— 同一状态两种观感。

### 3. 最亮的地方在四角

亮带是**无限长的直线**，亮核一路穿到屏幕四角。而四角正是四块文字面板（关于 / 近况 / 小岛秀夫 / 平沢進）所在；四个方向中点反而是最暗的。
实测（X 态）：四角 `rgb(31,31,38)`，上下边中点 `rgb(20,20,26)`。
视线被拉向空角，文字对比也被吃掉一点。

### 4. 合拢的幅度是随机的

从任意夹角出发各走最短路径：如果点击那一刻两条带接近平行，合拢到 0° 只需移动几度 ——
**1 秒的动画看起来像什么都没发生**；换一次点击又可能是 90° 的大甩动。同一个操作，反馈强弱不一致。

### 5. 附带：手势语言太像

进板块（1s 合拢）、同轴切换（1.4s 张开再合）、板块↔板块（途中闪 X）三者都是角度变化，
肉眼区分度低；配合第 1 条的亮度起伏，连续点击会觉得背景在抽动。

## 四、量化数据（1440×900）

- 层 150vmax = **2160px**；屏幕高 900px，沿渐变轴只覆盖元素高度的 **29%–71%**。
- v1 色标（24/40/60/76）：屏内几乎全是平台（`#2b2c38` 与 `#333440` 只差 8/255），
  屏边亮度仍有 27–29，与峰值 51.7 只差 1.9 倍 → **看不出带子的边界，整屏发灰**。
- v2 色标（38/45/55/62）：亮核半高半宽 **HWHM 189px**、屏边亮度 **19.4**、峰值 **51.7**、对比 **2.7×**；
  中线剖面：50px→48.6、150px→37.6、250px→22.4、300px 之后稳定在 ~20。
- 也就是说：**收窄只能靠色标位置**，层尺寸已接近「旋转不露边」的下限（理论值约 118vmax）。

## 五、这套东西里真正有效的零件（可复用）

1. **`mix-blend-mode: lighten` + 同款渐变**：重叠处取较亮者，合拢成一条时亮度与单条完全一致，
   交叉点也不会过曝 —— 解决了「颜色重叠导致视觉不和谐」。
2. **`bgTarget(cur, want, ccw)`**：目标 = `want + 180k` 中离当前最近的一个；正好 90° 平局时按方向定向。
   比「强制顺时针转半圈」更可控，剪刀合拢永远对称。
3. **脉冲目标写绝对角度**（`want ± 45`，收回 `want`），而不是「当前位置 ±45」：
   连续快速点击只会从当前位置重新靠拢，不会逐次外扩漂移。
4. **色标必须让「全暗点」落在 38%/62% 以内**，否则屏幕边缘停在半亮，带子没有边界。
5. **判断「同角度」用上一次的板块角度（`lastWant`）**，而不是当前几何角度 ——
   这样才能覆盖「同轴切换」与「重复点击当前板块」两种需要脉冲的情况。

## 六、如果要重做，先回答这几个问题

1. **X 是稳定态还是周期态？**
   要稳定 X，两条带必须同向等速（刚体）；要方向互异，就必须接受每 15 秒塌成一条线。
   这两者不可兼得 —— 这是这次失败的根因。
2. **最亮处允许落在哪？**
   长直线必然穿到两个对角；若不想让四角最亮，要么把带轴偏移（22.5°）、
   要么改用「中心径向柔光 + 短光刃」而不是贯穿全屏的长带。
3. **切换反馈的幅度要不要归一？**
   若允许每次幅度不同，就得接受「有时像没反应」。
4. **亮度起伏的容忍度？**
   任何「一条 ↔ 两条」的形态变化都会带来整屏平均亮度差；要彻底消除，形态必须恒定。
